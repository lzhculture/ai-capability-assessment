# AI 使用能力诊断评估 · 微信小程序源码

> ⚠️ **已废弃**：本项目已于 2026-09 取消小程序、改为网页版。本目录为**历史遗留源码（v0.6），不再维护**。当前产品见网页版 `web/` + `server/`，技术落地见 `产物/05-网页版落地方案.md`，版本演进见根目录 `系统更新日志.md`。以下原文保留作历史参考。

APCA（AI Personal Capability Assessment）个人版小程序，**零服务端**实现：题库内置在工程里，
所有作答数据只存在用户手机本机，不上传、不埋点、不绑身份。

- 源码版本：**v0.6.0**（对应题库 v0.3.0）
- **产品定位**：APCA 本身是**通用个人 AI 能力测评**（6 维度 / 4 等级 / 30 题），是主入口；行业专项（招投标 / 制造业 / 连锁品牌和门店企业）是**可选加测模块**，每个都是独立「模型」——有自己的测试标准（维度权重）与题库（各 18 题），既可随通用卷加测，也可**单独成卷**。
- 目标能力：6 维度诊断 → 四级定级 → 雷达图 → 学习地图 → **逐题复盘（规则版个性化解读）** → **结果海报分享**
- 上手方式：微信开发者工具 → 导入项目 → 选本目录 → AppID 先用「测试号」即可直接跑
- 零服务端：题库内置、数据只存本机，海报与复盘均为纯本地计算，不调用任何大模型 API

## 2. 计分口径（与 HTML Demo v0.3 完全一致）

| 项 | 口径 |
|---|---|
| 选项映射 | A=0，B=33.3，C=66.7，D=100 |
| 维度分 | 该维度下所有已答题得分取平均 |
| 综合分 | 6 个维度分的平均值（等权） |
| 等级 | L1 摸索 0-25 / L2 指令 26-50 / L3 流程 51-75 / L4 系统 76-100 |
| 未答题 | 不计入，交卷前会提示「还有 N 题未答」 |

## 3.1 通用 vs 专项（重要定位）

APCA 不是"招投标 / 售前 / GEO 专项测评"，它是一套**通用个人 AI 能力测评**。专项是叠加在通用之上的可选模块：

| 维度 | 通用版（主入口） | 专项模型（如招投标专项） |
|---|---|---|
| 题目 | 30 道通用题 | 6–7 道行业题（自建题库） |
| 测试标准 | 6 维度等权（与 Demo 一致） | 该专项自带的维度权重（`packs.js` 的 `weights`） |
| 入口 | 首页「开始通用测评」 | 首页勾选后**加测**，或点「仅测此专项」**单独成卷** |
| 计分 | 等权 6 维平均 | 用该专项权重加权 |
| 定位 | 产品本体，全员普查 | 可选加测，也可独立成一份专项测评 |

组卷逻辑：`buildQuestions(packId, mode)`，`mode` 为 `blended`（通用+专项，默认）或 `standalone`（只做专项）。
专项的"自己的测试标准"写在 `data/packs.js` 每个包的 `weights` 字段里（D1–D6 权重和为 1），专项单独成卷时由 `utils/calc.js` 按该权重计分。

## 5. 已知限制

- **Canvas 雷达图**：用旧版 `wx.createCanvasContext` 实现（兼容性最好）。若迁移到 Canvas 2d 新接口，改 `components/comp-radar/comp-radar.js` 的 `draw()`。
- **进度条组件**：小程序原生不支持 `computed`，已改用 `observers` 派生百分比，不要改回 `computed`。
- **退出拦截**：依赖 `wx.enableAlertBeforeUnload`（基础库 2.12+），低版本自动降级为静默保存。
- **数据不可迁移**：换手机 / 清微信缓存后历史记录丢失，这是零服务端设计的必然代价，已在「关于」页明示。
- **海报保存到相册**：依赖 `wx.saveImageToPhotosAlbum`，需在「小程序管理后台 - 用户隐私保护指引」勾选「相册 / 添加到相册」，否则部分基础库会拦截。无二维码图片时自动降级为占位块（不会崩）。
