# 个人 AI 办公能力测评 · 技术落地方案（网页版）

> **范围**：把 APCA 设计原型（`产物/00-总览分析.md`、`01-指标体系.json`、`02-题库.json`、`04-行业特化题包.json`）落地为**纯网页版**产品。
> **形态**：2026-09 起项目取消小程序、改为网页版。本方案即当前线上产品的技术实现，部署于 http://<服务器IP>:8787/。
> **版本口径**：题库/构建版本 `questionSetVersion`（见 `web/data.js` 与 `系统更新日志.md`）；设计文档的产品版本（v0.1–v0.7）为小程序阶段，其指标体系与题库仍适用。

---

## 1. 目标 & 边界

### 1.1 一句话定位
个人 AI 能力「诊断 + 学习」轻量工具：3 分钟选场景，5–10 分钟答题，立刻出六维雷达图 + 综合等级 + 30 天学习地图 + 可分享摘要。

### 1.2 范围
| 模块 | 已落地 |
|---|---|
| 测评站 | 首页（隐私声明 + 6 维介绍 + 选卷）/ 答题页（进度条 + 场景 + 4 选项 + 上下题）/ 结果页（等级卡 + 雷达 + 维度明细 + 3 建议 + 学习地图 + 逐题复盘）/ 历史 / 关于 |
| 管理后台 | 密码登录 / 汇总统计（等级·维度·公司·岗位·批次·趋势）/ 人员清单 / 题库与规则库查看 / 删除清空 |
| 数据汇聚 | 由 `server.js` 托管时，测评提交同步落库，后台可看全部测评人 |

### 1.3 明确不做（当前）
- 不做强制账号体系（不登录，作答默认存浏览器本机）
- 不绑具体公司名（遵循文档规范，留空或"本企业/贵司"通用表述）
- 不做生成式 AI 解读（第 ③ 层，需服务端 + API 成本，单独立项）
- 不做实时排行榜 / 付费 / 广告

### 1.4 价值主张
- 个人侧：不卷分数，给可执行的下一步
- 企业侧：一键分发到员工，后台按批次/部门汇聚能力图谱
- 平台侧：零安装跨平台，内网/公网/公众号外链均可承载

## 2. 总体架构

```
┌──────────────────────────────────────────────────────┐
│                    浏览器 (用户)                       │
│   首页 → 答题 → 结果(雷达/等级/复盘) → 历史/分享       │
│   作答进度/历史存 localStorage（本机，可断点续答）       │
└───────────────────┬──────────────────────────────────┘
                     │  HTTP 静态资源 + /api
┌───────────────────▼──────────────────────────────────┐
│              server.js（零依赖 Node 服务）             │
│  ├─ 静态托管 web/  →  index.html（测评站）             │
│  │                      admin.html（管理后台）         │
│  ├─ POST /api/submit  → 记录落库 server/data/records.json │
│  └─ /api/admin/*     → 鉴权 / 统计 / 人员 / 题库        │
└───────────────────────────────────────────────────────┘
                     ↑ 构建产物
┌──────────────────────────────────────────────────────┐
│   源题库  miniprogram/data/*.js  (core.js / packs.js …) │
│        │  tools/build-web-data.js  （含选项乱序）        │
│        ▼                                               │
│   产物  web/data.js  →  window.APCA_DATA                │
└──────────────────────────────────────────────────────┘
```

> **零强制服务端**：纯静态分发（直接打开 `index.html`）也能完整测评，数据只留本机；要汇聚团队结果才需要 `server.js` 托管。

## 3. 目录与数据模型

### 3.1 前端目录（`web/`）
| 文件 | 职责 |
|---|---|
| `index.html` | 测评站入口 |
| `app.js` | 答题 / 计分 / 复盘 / 历史 / 分享 逻辑 |
| `data.js` | 题库（`window.APCA_DATA`，由构建脚本生成，含每题 `scores` 映射） |
| `style.css` | 样式 |
| `admin.html / admin.js / admin.css` | 管理后台 |

### 3.2 题库构建（源 → 产物）
- **源**：`miniprogram/data/core.js`（30 通用题）+ `packs.js`（3 专项各 18 题）+ `dimensions.js` / `levels.js` / `question-types.js` / `reports.js`
- **构建**：`tools/build-web-data.js` 读取源 → 对每题做**确定性乱序**（`tools/lib/shuffle.js`）→ 输出 `web/data.js`
- **乱序保证**：选项文本连同分值一起换位，解析中字母引用同步重映射；同一题每次构建结果一致（可复现）

### 3.3 计分模型
- 固定映射 `A=0 / B=33.3 / C=66.7 / D=100`，但**每题独立 `scores` 映射**（乱序后 D 未必是 100 分）
- 维度分 = 该维度已答题得分均值；综合分 = 6 维均值（等权，blended）
- 专项 `standalone` 模式：按该专项 `weights`（维度权重，和为 1）加权
- 等级：L1 摸索 0–25 / L2 指令 26–50 / L3 流程 51–75 / L4 系统 76–100

### 3.4 服务端记录（`server/data/records.json`）
每条记录含：总分 / 等级 / 六维得分 / 测评卷 / 逐题作答 / 测评人信息（姓名·公司·岗位·批次·备注）/ 终端 `clientId` / 时间戳。写入先写 `.tmp` 再原子 `rename`；容量上限 20000 条。

## 4. 关键流程

### 4.1 主流程
```
[首页] --选卷(通用/加测/单独成卷)--> [答题页] --答完--> [结果页]
   ^                                          |
   |-- 重新测试 / 复制摘要 / 历史 <------------+
   +-- 历史项回看 <-- 首页成长记录
```

### 4.2 中断保护
- 进度存 `localStorage`，重进提示"继续上次 / 重新开始"
- 分享链接：`#r=<base64>` 编码完整记录，对方打开即看结果（不依赖服务端）

### 4.3 后台汇总
- 测评提交时，若由 `server.js` 托管，额外同步一份到服务端 `/api/submit`
- 后台按 等级 / 维度 / 公司 / 岗位 / 批次 / 时间趋势 多维统计，支持单条删除与清空

## 6. 构建与校验（改题库必跑）

```bash
node tools/build-web-data.js        # 源题库 → web/data.js（升版本号见 build-web-data.js）
node tools/verify-web.js            # 计分与一致性（含锚点/长度均衡/系统更新日志/版本同步门禁）
node tools/verify-web-dom.js        # 真实 DOM 全流程（需 agent-browser 无头浏览器）
node tools/verify-wiring.js          # 前后台接线静态校验
node tools/verify-merge.js           # 专项合并出分校验
node tools/verify-server.js          # 服务端端到端（托管/鉴权/统计/删除）
node tools/check-option-balance.js --ratio 1.5   # 选项长度均衡扫描
node tools/check-analysis-consistency.js         # 解析与锚点一致性扫描
```
五项校验共 **430+ 断言**，全绿方可部署。

## 7. 部署上线

```bash
# 1) 同步前端（幂等）
rsync -avz --delete -e "ssh -i ~/.ssh/你的服务器密钥.pem" web/ 部署用户@<服务器IP>:<部署目录>/web/
# 2) 版本说明留档
scp 系统更新日志.md 部署用户@<服务器IP>:<部署目录>/系统更新日志.md
# 3) 重启服务
ssh 部署用户@<服务器IP> "sudo systemctl restart apca.service"
# 4) 验证
curl -s http://<服务器IP>:8787/data.js | grep questionSetVersion
```

**发版惯例（自 v0.8.2 固化；v0.8.5 起追加 GitHub 同步）**：

1. 改题库 / 计分 / 用户可见行为 → **只改 `tools/build-web-data.js` 里的 `questionSetVersion` 一处** → 重建 `web/data.js`；
2. 同步文档：`系统更新日志.md` 新增置顶条目，并同步 `README.md`、`产物/00-总览分析.md`、`产物/05-网页版落地方案.md`；题库内容变更时还必须重跑 `tools/build-archive-snapshots.js` 重导产物快照（受 §1.13 门禁约束）；
3. 跑五件套校验——漏更文档会被门禁拦下（§1.7 系统更新日志 / §1.8 版本号单点真值 / §1.9 README 同步 / §1.10 HTML 版同步 / §1.11 固定字母宣称 / §1.12 学习地图 30 天 / §1.13 产物快照与真源一致）；
4. rsync + 上传 `系统更新日志.md` / `系统更新日志.html` → 重启 → 线上验证版本号；
5. **同步至 GitHub 仓库**（v0.8.5 起固化）：执行 `./tools/sync-to-github.sh`，自动跑五件套校验 + 写带版本号的 commit + `git push origin main`。详细见 `GITHUB.md`。

## 9. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 题库内容被质疑/举报（敏感场景） | 中 | 持续审核；保留"用户反馈"入口，快速响应 |
| 个人结果误读导致焦虑 | 中 | 文案反复强调"仅用于培训规划，不涉及考核"；不发证书、不进排行榜 |
| 单点服务故障 | 低 | 进程守护（systemd）；定期备份 `server/data/records.json` |
| 改题库引入长度/锚点失衡回退 | 中 | 构建后必跑 `check-*` 扫描 + 五件套校验门禁 |
| 历史记录与新版题库错位 | 低 | 锚点迁移逻辑按上线时点自动换算（见 v0.8.1） |
| 测评人信息留空导致后台汇总无法按公司/岗位分组 | 低 | v0.8.2 起姓名/公司/岗位必填（可虚拟填写），未填写无法开始答题 |
