版本口径说明
- questionSetVersion（web/data.js 中的题库版本）：随题库内容变更递增（v0.7 → v0.7.1 → v0.8 → v0.8.1 → …）；
- 产品功能版本（v0.1–v0.7）：小程序/网站架构迭代；
- 每个条目包含：变更内容、验证结果、部署状态。
发版惯例（自 v0.8.1 起固化）
1. 任何影响题库内容、计分逻辑或用户可见行为的发版，必须同步更新本文件，新增条目置顶；
2. 版本号变更时同步修改 tools/build-web-data.js 中的 questionSetVersion；
3. tools/verify-web.js 已设强制门禁（漏更说明文档无法通过回归）：
- §1.7：当前 questionSetVersion 若无对应 CHANGELOG 条目 → 校验直接失败；
- §1.8：tools/build-web-data.js 与 web/data.js 版本号不一致（半成品发版）→ 失败；
- §1.9：README.md 版本速览表未含当前版本号 → 失败；
- §1.10：系统更新日志.html 缺失 / 不含当前版本 / 比 md 旧 → 失败；
- §1.11（v0.8.4 起）：固定单字母期望分超出「不可套利」区间 → 失败（防对外宣称再次失实）；
- §1.12（v0.8.4 起）：学习地图 tips 总数 ≠ 30 或仍有 idx % 5 错位 → 失败；
- §1.13（v0.8.4 起）：产物/02-题库.json、产物/04-行业特化题包.json 与真源不一致 → 失败；
  • §1.6 + §1.6b（v0.8.6 起）：§1.6 改为直接调用独立脚本 tools/check-analysis-consistency.js（单一真值源）；§1.6b 要求解析里「本题「最可能」是 X」的 X 必须等于该题满分锚点 → 失败。
4. 文档同步范围（自 v0.8.2 起固化，用户明确要求）：每次系统更新，除本文件外还需同步——README.md（版本速览表 + 功能描述）、产物/00-总览分析.md（版本链路与产物清单）、产物/05-网页版落地方案.md（版本表与路线图）。涉及形态/口径变化时同步其余 产物/*.md。自 v0.8.4 起，题库内容变更时还必须重跑 tools/build-archive-snapshots.js 重导 产物/02、产物/04 快照（受 §1.13 门禁约束）。
5. 部署顺序：本地改码 → 升版本号（只改 build-web-data.js 一处）→ node tools/build-web-data.js 重建 web/data.js → node tools/build-archive-snapshots.js 重导产物快照 → 跑 tools/build-qrcode.py + tools/build-update-html.js 产出 web/qrcode.png 与 系统更新日志.html → 更新本文件与上述文档 → 跑五件套校验 → rsync 部署 web/ + 上传 系统更新日志.md / 系统更新日志.html → 重启 测评服务 → 线上验证版本号。
6. 同步至 GitHub 仓库（自 v0.8.5 起固化）：完成线上验证后执行 ./GitHub 同步脚本，自动跑五件套校验、写带版本号的 commit message、git push origin main。详细操作与故障排查见 GITHUB.md（含 SSH key 配置、commit 规范、安全自查清单）。

[v0.8.11] - 2026-09-18 · 移除内置默认口令 + 开源许可证落定#

触发#

为「将来是否转公开仓库」做前置排查时（清单见根目录 内部过程文件/开源前清理清单_个人测评），逐文件扫描出两处现在就该修的缺陷：

  1. 口令硬编码：server/server.js 写的是 process.env.APCA_ADMIN_PASS || '<旧默认口令>'。意思是没设环境变量时后台密码就是那个写死的值。仓库一旦转公开，等于把后台口令贴给所有人看；而"照文档跑起来、却忘了设环境变量"恰恰是最常见的漏改场景。
  2. 版权与许可证三处不自洽：根 README.md 的版权声明写的是"仅授权某一外部域名下免费使用、不得用于其他域名、不得商用"——这既与开源口径直接冲突，授权对象也不属于本项目自己；README.md 引用的 ./LICENSE 文件根本不存在（死链）；实际存在的 web/LICENSE 与 LICENSE.template 是"免费使用但禁止商用、禁止部署到其他域名"的个人作品许可，不是开源许可证。

主要变更#

  • 服务端不再内置任何口令 — server/server.js：未设置 APCA_ADMIN_PASS 时拒绝启动（退出码 1），并打印四行处置指引（给出完整命令、说明只想做问卷可直接打开 web/index.html 走本机模式）。删掉 USING_DEFAULT_PASS 变量。注意：只想做测评的人不经本服务，这条变更不影响问卷作答。
  • 启动日志不再打印明文密码 — 原逻辑在"使用默认密码"时会把密码原文打进控制台；现在一律输出 ******，并移除那条默认密码告警分支（已经不可能触发）。
  • 许可证改为 MIT — 新增仓库根目录 LICENSE（MIT 正本，Copyright © 2026 jmount）；LICENSE.template 由原"限域名、禁商用"的个人作品许可改写为 MIT 副本 + 部署登记信息（部署位置/对外地址/版本三项占位保留，tools/build-license.py 的双服务器渲染机制不变）；根 README.md 版权声明改写为"源代码按 MIT 许可证开源"。
  • 文档同步 — server/README.md：启动命令补 APCA_ADMIN_PASS、密码表改为"无默认值（必填）"、部署建议里的"改掉默认密码"改为"设置一个强密码"；根 README.md 的服务器差异对照表相应调整。

部署须知（重要）#

本次改了服务端启动行为。两台在用服务器的服务配置里都已经带着 APCA_ADMIN_PASS（公网机在 systemd 的服务配置里，内网机在 /etc/apca/apca.env 里，由部署脚本随机生成），所以升级后重启不会起不来。但任何新装的实例都必须先设这个变量，否则服务会拒绝启动——这是有意设计的。

P0 计分正确性（生产事故级）：

  • P0-3 门禁补维度不均衡回归用例：tools/verify-server.js 新增 2 条永久用例——①bid standalone（D4=0 其余 100）期望服务端重算 total=78.0；②merged 路径（核心全 0 + 专项全 100）期望等权 ≈36.3。此前用例全是「专项全 100 分」，两套加权模型结果都是 100，天然覆盖不到该回归。
